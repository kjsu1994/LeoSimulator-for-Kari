화면하는 일
상단 재생 도구현재 결과의 재생·일시 정지, 시각 이동, 재생 속도 조절과 결과 불러오기

사용자 설명서 · 02

설치와 첫 실행

Windows x64 환경에서 배포 ZIP을 모두 풀고 sim-ui.exe를 실행합니다.

실행 전 준비

Windows 10 또는 11, Microsoft Edge WebView2 Runtime, Windows UI 호스트에 필요한 .NET Framework를 사용합니다. 압축을 푸는 폴더에는 쓰기 권한이 필요합니다.

  1. ZIP 전체를 쓰기 가능한 폴더에 풉니다. sim-ui.exe는 settings, engine, data와 같은 배포 폴더에서 실행합니다.
  2. 오른쪽 새 시뮬레이션에서 시험 조건을 기본 통신으로, 알고리즘을 Dijkstra · 지연 최소로 선택합니다.
  3. 실행을 누르고 계산 완료를 확인합니다. 지도와 수신 결과가 새 실행으로 전환됩니다.
  4. 시간 슬라이더를 움직이거나 재생을 눌러 지도를 확인합니다. 다시 열 수 있도록 data/runs 안의 실행 ID 폴더를 보관합니다.
여는 파일사용 범위
sim-ui.exe조건 수정, 새 실행, 비교 실행, 결과 열기 및 지도 재생
index.html직접 열면 저장된 결과를 재생합니다. 계산 및 INI 수정은 EXE에서 진행합니다.
EXE에는 Python 실행 환경이 포함됩니다. OMNeT++, INET, WSL, Docker 또는 원본 프로젝트를 준비할 필요가 없습니다.

시험 조건과 알고리즘 선택

시험 조건은 위성망·송신·장애 등 입력을 정하고, 알고리즘은 그 안에서 경로를 고르는 방법을 정합니다.

추가 시험 표시는 기본 목록에 더해 INI에 등록된 전체 시험 구성을 보여줍니다. 조건을 선택하면 목록 아래 설명과 설정 요약이 갱신됩니다. 실행을 누르면 선택한 조건으로 새 결과가 생성됩니다.

조건기본 설정에서 확인하는 내용
기본 통신기본 위성군과 여러 송신 노드에서 전달률·지연·계획 경로 확인
반복 링크 장애60·120·180초마다 고정 출발·목적 흐름의 기준 경로에서 위성 간 링크 하나를 각각 30초 동안 끊어 우회와 수신 재개 확인
무작위 링크 장애30~570초 사이에 무작위 링크 장애 20건을 각각 30초씩 적용해 전달률·지연 확인. 같은 입력과 장애 시드는 동일 장애 일정을 재현

사용자 설명서 · 04

알고리즘과 비교 목적

알고리즘을 고르면 선택한 INI 구성에 저장됩니다. 저장된 지도와 수신 결과는 새 실행이 끝날 때까지 그 실행의 데이터를 표시합니다.

화면 표시경로 선택 기준
Dijkstra · 지연 최소전파 지연을 최소화하는 경로
Dijkstra · 홉 최소홉 수를 최소화하는 경로
MCSR-LS지연 우선
MCSR-TS처리량 우선. 지연 상한을 지정할 수 있음
MCSR-HR신뢰성 우선. 지터 제약을 지정할 수 있음

시험 목적별 선택

  • 구성을 처음 확인할 때는 기본 통신을 한 번 실행해 지도·송수신 상태를 확인합니다.
  • 경로 복구를 비교할 때는 반복 링크 장애 또는 무작위 링크 장애를 선택하고 비교 실행을 사용합니다.
  • 부하에 따른 차이를 살펴볼 때는 패킷 크기를 유지한 채 송신률이나 송신 노드 수를 단계적으로 바꿉니다. 같은 단계에서는 입력을 고정한 채 알고리즘을 비교합니다.
링크 장애 비교는 같은 물리 사건과 공통 SRD에 대해 진행합니다. 반복 링크 장애의 대상은 해당 시각의 기준 경로에서 정해집니다.

조건 수정과 기본값

조건 수정에서 변경한 값은 INI에 저장을 누르면 다음 실행에 적용됩니다.

  1. 시험 조건을 선택한 뒤 조건 수정을 누릅니다.
  2. 기본 설정, 트래픽, 링크 및 장애·환경 조건을 확인합니다. 항목 옆 ⓘ에서 단위와 변경 효과를 읽을 수 있습니다.
  3. 제공 설정을 다시 불러오려면 기본값을 누릅니다. 적용하려면 INI에 저장, 이번 편집을 버리려면 취소를 누릅니다.

기본값은 선택한 구성의 제공 섹션을 기준으로 하며 상속값은 현재 상위 설정을 따릅니다. 직접 추가한 구성은 제공 기본값이 없으므로 값을 직접 편집합니다.

조정할 값관찰할 항목
위성 수·궤도면·고도위성 수는 궤도면 수로 나누어 떨어져야 합니다. 접속 기회와 경로 길이의 변화를 관찰합니다.
송신률·송신 간격·패킷 크기발생 패킷 수, 큐 대기와 폐기, 처리량 변화를 관찰합니다.
최소 고도각·링크 용량·큐접속 범위, 병목 및 링크 포화의 변화를 관찰합니다.

INI와 외부 일정 편집

INI 상세에서 적용된 설정 키와 값, 섹션 및 상속 정보를 확인합니다.

  1. 새 시뮬레이션에서 INI 상세를 펼치고 INI 파일을 누릅니다.
  2. 현재 실행 설정의 진입 파일은 settings/simulations/Network/omnetpp.ini입니다. 파일을 UTF-8로 저장하고 설정 새로고침을 누릅니다.
  3. 새 구성은 [Config 이름]과 extends로 만들 수 있습니다. 추가 시험 표시를 켜고 새 구성을 선택합니다.
내용형식 또는 위치
링크 직접 장애12-13@60+30 → 위성 12와 13 사이 링크를 60초에 30초간 끊음
기준 경로 장애route@60+30 → 기준 경로의 위성 간 링크를 60초에 30초간 끊음
계획된 ISL 개폐time,event,satA,satB 열이 있는 CSV. event에는 failure 또는 restore를 사용하며 시간 단위는 초
지역 혼잡환경 조건에서 링크, 위성, 궤도면, 지도 구역 등을 지정해 용량·버퍼·지연·지터·손실을 설정

상대 경로는 진입 INI의 위치를 기준으로 해석합니다. 개폐 일정은 고정 격자에 있는 링크를 사용합니다. 기존 구성 형식과 지원 키는 README.md의 시나리오 설정 항목에서 확인할 수 있습니다.

사용자 설명서 · 07

지도 재생과 결과 가져오기

현재 재생 중인 지도와 새 시뮬레이션 설정은 화면의 상태 표시에서 구분합니다.

열기 방식표시되는 내용
실행 결과 열기manifest.json이 있는 개별 실행 ID 폴더를 선택합니다. 보관된 설정과 사건을 사용해 위성 위치·링크·경로를 재생하며, 저장된 수신 통계를 표시합니다.
CSV만 열기routes.csv의 시각, 출발·목적, 위성 경로와 계산 지연을 읽습니다. 현재 지도와 일치하는 CSV는 함께 재생할 수 있습니다. 다른 실행의 CSV를 열면 기존 지도를 시각이 고정된 참고 화면으로 표시합니다.
  1. 실행 결과 열기에서는 data/runs 상위 폴더 대신 data/runs/<실행 ID> 폴더 전체를 선택합니다.
  2. 슬라이더 또는 −1s / +1s로 관찰 시각을 이동하고, 재생 속도를 바꿔 움직임을 확인합니다.
  3. 지도에서 위성·지상 노드에 마우스를 올려 정보를 읽습니다. ISLs, GSLs, Coverage, Active Routes, Labels 체크박스로 표시 항목을 조절합니다.
  4. 출발·목적 필터로 관심 경로를 찾고 Recent Planned Routes 표에서 계획 경로를 확인합니다.
CSV의 경로 번호와 위성 ID만으로는 위성의 좌표, 지상 노드의 이동, 전체 ISL·GSL, 수신 패킷 통계를 재구성할 수 없습니다. 전체 재생에는 실행 결과 폴더가 필요합니다.

수신 결과와 복구 지표 읽기

지도와 경로 표는 계획 경로를, 수신 결과는 패킷이 실제로 처리된 시뮬레이션 결과를 보여줍니다.

항목읽는 기준
전달률수신 ÷ 발생 × 100. 발생에는 위성 접속·초기 경로를 찾지 못한 시도도 포함
수신 지연·지터수신한 패킷의 종단 간 지연과 그 변동. 수신이 없을 때 빈 값은 미관측
처리량수신한 데이터 페이로드를 집계 시간으로 나눈 값. 그래프에서 시간별 변동 확인
첫 수신 / 안정 복구장애 이후 생성된 첫 패킷의 수신 시각과, 이후 두 관측 구간에서 정해진 전달 기준을 만족한 시각을 각각 확인
제어 전송·정보 수렴상태 전달에 사용한 전송량과 장애 정보가 대상 노드들에 반영되기까지의 시간
경로 표의 Predicted propagation은 계획 시점의 계산값입니다. 수신 지연에는 전송과 큐 처리 등이 반영되므로 수신 결과에서 확인합니다.

비교 실행과 반복 실험

비교 실행은 새 결과를 계산합니다. 수신 결과의 실행 비교에서는 완료된 결과를 다시 비교합니다.

  1. 시험 조건을 선택하고 비교 실행을 누릅니다. 비교할 알고리즘을 체크합니다.
  2. 반복 횟수 1회·10회·30회를 고릅니다. 전체 실행 횟수는 선택한 알고리즘 수 × 반복 횟수입니다.
  3. 필요하면 고급 설정에서 시작 시드, 준비 구간과 종료 관측 구간을 설정하고 실행합니다.
  4. 이전에 계산한 결과는 수신 결과 → 실행 비교에서 파일 또는 보관 이력으로 엽니다. 완료된 반복 결과는 반복 실험 → 통계 보기에서 확인합니다.

같은 시드의 알고리즘은 공통 송신 입력·장애 사건·SRD를 사용합니다. 준비 구간에서 생성된 패킷은 측정에서 제외되고, 종료 관측 구간에는 새 데이터 패킷 생성을 멈춥니다.

시드가 달라도 실제 입력이 고정되면 결정적 재현 시험에 해당합니다. 조건 다양성은 송신 부하, 장애 강도 또는 위성 구성을 바꾼 별도 시험에서 확인합니다.

결과 보관과 문제 해결

결과는 실행 ID 폴더 단위로 복사하면 다른 PC에서도 열 수 있습니다.

파일 또는 폴더보관 이유
manifest.json실행 식별자와 파일 해시. 나머지 파일과 함께 유지
config/ · inputs/ · normalized.json당시 INI, 외부 입력, 실제 적용한 정규화 설정

자주 발생하는 상황

증상확인 방법
EXE 창이 뜨지 않거나 지도가 검게 보임배포 ZIP을 전체 해제했는지, data/earth.png가 있는지, WebView2가 설치되었는지 확인합니다. 실행 중인 다른 sim-ui 인스턴스가 있으면 닫고 다시 엽니다.
폴더를 열 때 오류가 남개별 실행 ID 폴더를 선택했는지 확인합니다. 누락되거나 수정된 파일은 원래 결과에서 다시 복사합니다.
설정이나 실행 버튼이 비활성index.html을 직접 열었다면 sim-ui.exe로 전환합니다. 실행 중이라면 완료되거나 중지될 때까지 기다립니다.
비교가 다른 조건으로 표시됨모델·엔진, 공통 시나리오, 장애 사건 및 측정 구간이 같은지 확인합니다. 필요하면 비교 실행으로 다시 생성합니다.

중지하거나 실패한 비교는 직전 완료 결과를 유지합니다. 이미 끝난 개별 실행은 각 실행 폴더에서 확인할 수 있습니다.
